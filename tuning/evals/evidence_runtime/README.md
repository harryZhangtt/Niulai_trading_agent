# Evidence runtime conformance evaluation

This is the first consumer of a lightweight sealed evaluation contract. It
checks a historical earnings fact, exact phase resume, complete source accounting,
and cache success/failure/concurrency. It is development/unblinded, with known
answers and a guided reconciliation schema. Ten assertions sharing one run are
not ten independent samples and establish no investment or broad reasoning gain.

`cases.json` separates questions/inputs from expected outcomes, with criticality,
metrics and one budget. `contracts.py` seals immutable references and grader
closure hashes, registers attempts before execution, and checks source pins,
full roster, metrics and budgets at completion. `grade.py` performs host-side
source/state checks; it does not accept agent-provided grades. Current network
coverage is separate from conformance. Missing/blocked provider rows cannot be
removed to improve a rate. The baseline/candidate API requires the same sealed
cases, grader and budget for a paired comparison; this round is candidate-only.

The runtime acceptance adapter seals before scheduling and begins before work,
then finishes through the host callback. Artifact and attempt state is private
and workspace-local. Changed data, expectations, graders or budgets require a
new sealed contract; prior failures and unknown claims remain visible. It is an
integrity and protocol guard within this application, not a signed ledger, a
universal CI hook or OS isolation from a fully privileged developer.

For the main path see `docs/deployment/investment-research.md` and
`docs/deployment/runtime-acceptance.md`. Compare quality and cost independently.
A metadata cache hit is not a document read; matching source keywords is not
independent semantic or causal validation. Current semantic support is reviewed
against original passages, with deterministic checks limiting mechanical errors.


The scheduled development consumer passed all 10 host-graded cases on 2026-10-31;
overall source coverage remained partial. The private acceptance record is
`.job-runtime/acceptance/source-cache-resume-20261031-v2/record.json`, with
independent readback and verified owner notification. Shared-run latency/call/
token metrics appear on each case for context and must not be summed across
those case rows. Preserve the roster and its unknown/failed routes when reporting
retrieval and cache rates. 10/10 warm integrity hits did not imply 10/10 eligible
claim inputs: the observed eligible count was 9/10.
