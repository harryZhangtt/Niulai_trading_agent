# Complex quality-gate effectiveness screen v1

Designed before solver responses. This is a fresh synthetic development screen,
separate from the earlier atomic cases. It tests decisions from conflicting
artifact evidence, not live tuning execution or investment outcomes.

## Question and rivals

Does the explicit promotion-gate reference improve decisions beyond the existing
evaluation skill and local investment context?

- Target mechanism: distinguish the evaluated object, scope, actual failure and
  unavailable evidence even when a favorable summary or another defect competes.
- Rival: the existing evaluation skill already supplies enough guidance.
- Rival: a model can pass by always refusing acceptance or by copying verdict words.
- Rival: apparent benefit is a stochastic one-run difference rather than a stable effect.

## Case construction

Eight cases in four matched pairs. A separate case author reads the existing
experiment-design references and gate contract, not earlier cases or outputs.
A separate reviewer checks ambiguity, arithmetic, evidence sufficiency, label
balance and whether each pair changes only its declared decisive fact.

Use run/artifact IDs, source excerpts, version/timestamp records and plausible
distractors. Public packets must not include the gold answer or phrases such as
"all other requirements satisfied". Accept cases prevent always-blocking behavior
from receiving a perfect score. Inconclusive cases distinguish missing evidence
from established failure. Paired scope/object changes test semantic decisions
without requiring the same verdict in every superficially similar situation.

The author/reviewer and root know the key. This is not an independent protected
holdout. Only after review is the case file frozen and hashed; solver workers
receive no gold, prior responses, paired counterpart or arm label.

## Controlled comparison

- Control: evaluation skill and its required investment context, with the four-line
  promotion-gate addition removed and no promotion-gate reference text.
- Gate: identical context plus that addition and the current promotion-gate reference.
- Same model and inherited reasoning setting, case, 180-word output cap, output
  schema and allowed tools. Fresh context per case/condition. No routing difference.
- All tool access restrictions are instructions, not an OS-enforced boundary.
  No private data, protected investment cases or external research are used.

The explicit reference is the intervention. This does not compare all five skills
against an unguided model and does not establish an effect of the full skill set.
The gate and case keys are not edited during this screen.

## Outcomes and grading

Primary: exact accept/reject/inconclusive decision, wrong-object conclusions,
false acceptance, unwarranted rejection and unnecessary inconclusive outcomes.
Check all case and condition pairs; report failures individually.

Secondary: three anchored dimensions, each 0–2:

1. Evidence: 0 invented/contradicted; 1 relevant but incomplete; 2 identifies the
   decisive supplied artifacts and resolves the material conflict.
2. Scope/object: 0 wrong object or unsupported broad claim; 1 vague boundary;
   2 correct object and clearly bounded allowed claim.
3. Next action: 0 repeats/executes unsupported work or no useful action; 1 generic;
   2 smallest relevant evidence repair, fix or scoped adoption action.

Response IDs and order are blinded and shuffled for a separate grader. It first
scores an obvious good/bad calibration pair. Evidence IDs must exist; valid
alternative reasoning can earn credit. Do not reward a gold keyword or preferred
workflow. Root reviews all discrepancies and critical claims before unblinding.
Same-family grading and instruction-only isolation remain limitations.

## Interpretation, budget and stopping

Eight correct verdicts with no false acceptance or wrong-object claim constitutes
a clean screen. Anything less is diagnostic partial success, with the exact
failure preserved. Report paired relations and case-level results, not just a mean.
The gate has observed marginal benefit only if it improves correct/grounded
decisions without introducing a critical regression; one run cannot establish
statistical superiority. A tie supports no incremental effectiveness claim.

Budget: 16 solver responses, one case-design pass, one case-review pass and one
blind grading pass after calibration. One serialization repair is permitted for
missing/malformed artifacts; never rerun an unfavorable valid answer. No sweep
or skill edits in response to this set. If a failure suggests a refinement,
record the hypothesis and keep this set as development evidence.

Measure serialized instruction/output size with the existing tokenizer proxy if
available. It excludes reasoning, hidden host/tool instructions, billing and
caching. Do not claim dollar savings, latency improvement or long-session efficacy.

## Pre-freeze review cautions

The separate reviewer approved all eight cases without blocking edits. Grade the
explicit out-of-range 13/12 summary and reproduced grader bug, not decimal rounding.
For the missing-output case, 32 known points already reach the numeric threshold;
coverage is still incomplete. Credit valid artifact-grounded alternatives rather
than requiring every gold evidence ID or the exact wording of the key.
