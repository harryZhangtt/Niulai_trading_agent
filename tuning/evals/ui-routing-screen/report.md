# Independent UI routing screen — 2026-10-30

The separate UI router selected the required packages and material playbooks on
**8/8 cases**, without an unnecessary package. Both backend-only and prose-only
controls selected no UI skills. The overlapping state/browser request selected
async-state-reliability, Impeccable hardening and Playwright together.

| shadcn Dialog/component APIs | shadcn |

| Entity identity, unknown saves, visible states and rendered tests | Async state reliability, Impeccable, Playwright |
| Substantial visual direction and rendered inspection | Frontend design, Impeccable, Playwright |
| Backend-only repair | None |
| Release-note summary | None |
| Purposeful animation in an existing Motion app | Impeccable animation playbook |

A fresh worker received only the frozen UI policy/router and public requests,
without expected answers, prior conversation, skill bodies or web access. It
completed one pass with no semantic retry. Deterministic review checked complete
unique IDs, required/optional packages, material playbooks, real local resource
paths and unchanged source/packet hashes. This is instruction-level isolation,
not an OS-enforced access boundary. Cases are author-created visible development
material and must not be reused as claimed fresh validation.

The router itself is **564 tokenizer-proxy tokens**. Its complete supplied packet,
including policy, requests and response contract, is 1,295 proxy tokens; the
captured response is 481. These are serialized `o200k_base` text sizes, excluding
host instructions, reasoning, tools, caching and billing. Provider usage is
unavailable. The worker did not load the selected bodies: the larger context
figures in `results.json` model those subsequent loads rather than claim they
were consumed during this routing screen.

The matched cumulative difference is 9.78%; it is much smaller than the 73.72%
separate-decision difference. These calculations are scoped to the named local
resources, with the counterfactual limitation below.

`results.json` counts selected entrypoints and named playbooks both per separate
decision and as a cumulative session union, with per-file hashes. It reports an
all-seven-entrypoints floor that omits conditional references. Some Impeccable
playbooks are substantial: a selected session with them can exceed that floor.
It also includes a diagnostic counterfactual that loads all seven entrypoints
plus the **same** references, avoiding that asymmetry. The latter was added during
analysis to explain cost, rather than as a new preregistered adoption threshold.
Additional component/rule searches, Motion documentation, browser snapshots and
tool outputs are not priced here. Selective loading does not remove text already
loaded, and sessions eventually needing most packages retain much of that cost.

Routing accuracy does not demonstrate better visual output or reliable async
behavior. The isolated React/TypeScript fixture and rendered Playwright checks
provide separate execution evidence, documented in the
[frontend runbook](../../../docs/deployment/frontend.md). They do not establish
the quality, accessibility or failure behavior of an investment application or
prove the comparative effectiveness of the imported skills. No public-source or
local-fixture login was required; no MCP server was activated.

See `protocol.md`, `cases.json`, `results.json` and `summarize.py`. Raw packet,
response and source hashes are retained under ignored

tokenizer in `requirements.txt` with the workspace-local cache described in the
