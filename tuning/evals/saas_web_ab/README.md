# SaaS web add-on A/B, development

The live development comparison is recorded in [report.md](report.md): mixed
quality findings, incomplete add-on applicability, and a source-change gate
failure retained separately from descriptive assessments. No promotion occurred.

A is web search with the workspace add-ons **as actually available**. B is competent
normal web search. Both use the same native search/open/find backend and inherited
researcher model/effort in fresh contexts, the same question/cutoff/company roster,
output format and 12-provider-item/600-second budget. No closed-book baseline,
domain enablement, new adapter or production configuration change is part of A.

`protocol.json` fixes questions, metrics and failure/stopping rules.
`inventory.json` distinguishes executable, instruction-only, unavailable and
unwired capabilities. `reference.json` was built independently before trial
answers, with raw receipts in private mentor runtime state. It is not exhaustive
historical-vintage proof: retrieval occurred after cutoff, source publication days
were checked, and current page revisions remain a limitation. Valid new sources
may be adjudicated under the unchanged rubric.

Use existing sealed-contract/attempt gates. Reviewer receives randomized anonymous
answer labels/order, the same reference and rubric, without arm/process labels.
Record per-company dimension vectors and critical errors separately from calls,
latency and applicability. Provider permissions are procedurally restricted in
this host, not OS-isolated; actual backend identity/tokens/cost may remain unknown.
Do not claim statistical superiority from three company pairs or count an A
capability rejection as a failed provider request. The arm answer is judged
independently from its process trace; no source count or writing-style award.

This evaluates foreground agent research and current workflow add-ons. The
workspace CLI adapters still disable web search. No automatic SaaS web pipeline,
active MCP integration or scheduled runtime-engine rollout is installed by this
experiment. Any later integration requires its own runtime acceptance.
