# SaaS web search A/B — descriptive development result

A means **web search with our current add-ons**. B means **normal web search**.
The experiment does not assume that A is complete. No features or source domains
were enabled to improve its result.

The observed result is a tradeoff: A covered more recent requirements, B was faster,
and neither had an established critical error. This does **not** demonstrate an
isolated retry, cache or additional-provider benefit: those paths were unused.
The original sealed gate **failed** because an unrelated workspace instruction
changed during execution. The source assessments below are descriptive evidence,
not an accepted evaluation or promotion.

## Matched live task

One fresh researcher per arm investigated ServiceNow, Salesforce and Adobe:
latest material responses to AI disruption, recent adoption/monetization evidence,
economic mechanisms, counterevidence and unresolved paid-conversion information.
Both received the same questions, cutoff (`2026-10-31T04:54:10Z`), output schema,
inherited requested model/effort and 12-provider-item/600-second budget. Both used
native search and source opening in fresh agent sessions. The parent session's
old native transport circuit was not retried. This verifies the foreground host
route at this time; CLI adapters that disable web search remain unchanged.

The protocol, capability inventory, independent reference and grading source
closure were sealed before researcher answers. The reference builder did not see
the answers. A prior capability probe exposed ServiceNow facts to the supervisor;
these are development cases, not unseen holdouts. Page publication days were
checked, but exact historical page revisions were not archived independently.

A fresh reviewer received anonymous per-company X/Y labels, captured opened

or OS isolation. Order consistency is not a probability of correctness.

The supervisor subsequently checked A's raw regional Adobe search receipt: it
does support October 1 metering as a search excerpt. It still identifies September

the added adjudication narrows the uncertainty without rewriting the answers.

## What A actually exercised

A read the existing routing policy and source catalog. Three existing document
adapter compatibility probes returned `SOURCE_URL_REJECTED` before network access:
the current allowlist does not cover these SaaS domains. These are capability
rejections, not failed provider requests. Native source opening still succeeded.

The versioned acquire/read/compare actions, observation cache, paper adapters and
optional MCP routes were unused. No timeout or native transport failure occurred,
so retry and fallback effectiveness remain untested. Cache reuse and retrieval
hit rate also remain untested. A's early local instruction reads lack separate
raw shell receipts, which its trace discloses; native operations and compatibility
probes have retained receipts.

Both agents chose their queries and batching. B batched more operations; provider
response truncation and document choices can also vary. The 105-second elapsed
difference cannot be assigned entirely to infrastructure overhead. Any observed
quality difference is an as-available workflow observation, not a causal estimate
for a particular add-on. Actual backend model identity, tokens and cost were not
exposed by the host.

## Integrity gate and scope

At finish, both original attempt records failed with `EVAL_SOURCE_CHANGED` and
zero formally accepted cases. Only `AGENTS.md` differed from the 26-file sealed
closure: a recurring price/holdings sender authorization was added while the arms
ran. Removing exactly that added paragraph in memory reproduced the frozen hash;
the research code, rubric, reference and budgets were unchanged. The source was
not reverted, the seal was not rewritten, and the failed attempts were retained.
This demonstrates that the source-change guardrail actually rejected drift.

Run identity: `saas-web-ab-20261031`; contract version `1.0.0`. Private run state
retains the contract, pre-dispatch prompts, answers, raw tool outputs, anonymous
review, post-review adjudication, source-drift receipt and both failed ledger
results. `protocol.json`, `inventory.json`, `reference.json` and `grade.py` remain
the frozen development inputs.

Three correlated company pairs with one run per arm cannot establish statistical
superiority, investment alpha, outage resilience or scheduled-runtime readiness.
No add-on is promoted and no runtime/MCP configuration is changed. The immediate
useful findings are incomplete SaaS adapter coverage, search-only support gaps,
and date-kind precision. A later engineering change should target an observed gap
and earn a new sealed test; this comparison does not justify building a larger
platform or rerunning until A wins.
