# Investment Research — Financial Services

Use this adapter as the entry point to the eight research workflows plus the dedicated DCF and integrated financial-model workflows bundled from Anthropic financial-services. Treat upstream references as methodology, not as installed Claude plugins or active data connections. Read only the workflow needed for the current task. Apply the user’s compact, asynchronous app requirements through the adaptation rules below.

## Mandatory research harness

Read and execute [Research harness](references/research-harness.md) **before starting or resuming ticker research**. Reuse native Skills, plan tracking, subagent review, connected source tools and persistent artifacts; do not build a second agent executor. Default an unqualified ticker-research request to the full company or fund pipeline. Treat the user's examples and hypotheses as additional tests, never as permission to omit the other stages. Use a narrow profile only for an explicitly bounded factual request; it cannot produce a full investment recommendation.

Keep a versioned JSON run record outside Skills git using the bundled standard JSON Schema. Connect claim/source passages, topic coverage, reproducible models, actual check outputs, independent review and saved artifacts. Validate it with a maintained JSON Schema implementation and inspect the referenced evidence before a completed recommendation. Recheck after compaction, a source/model revision or delegated handoff. Missing/stale evidence or incomplete required work blocks a completed recommendation; report a partial result with precise gaps instead. Save artifacts and retain actual receipts before claiming publication. Schema validation establishes structural completeness, not semantic truth or a platform-wide tool block. Use native lifecycle hooks only where supported, trusted and observed; do not claim activation from a config file alone.

Require **profit scalability and value capture** as a separate evidenced topic in every full run. Trace demand/usage to billable units, effective price, variable/model/cloud/support costs, fixed costs, lost legacy revenue, recurring SBC, reinvestment and owner profit per share. Test whether more usage expands profit, scales it roughly linearly or compresses unit margins; identify whether suppliers, model/platform vendors, competitors or customers keep the surplus. Recalculate price/cost/mix sensitivities. Undisclosed unit economics remain explicit gaps with modeled sensitivities, never invented numbers or assumed positive operating leverage. For funds apply this to underlying holdings/industry and separately model wrapper costs/payoff.

## Apply the local adaptation

- Reuse saved scope, universe, thesis, cadence, and publication policies. Do not repeat upstream intake questions or formatting approval steps when the user has already supplied the answer or authorized recurring work. Ask only for materially blocking ambiguity.
- Default to compact structured findings and a phone-readable summary. Upstream slide, workbook, chart-count, and page-count requirements apply only when that artifact is requested. Use the environment's document, presentation, and spreadsheet skills for requested exports; do not assume Claude-specific tools, paths, Office add-ins, or example files exist.
- Discover actual available tools. The proposed market backend operations may not exist yet. Never invent calls or claim to save results without a successful write. If storage is unavailable, deliver a clearly labeled draft and identify the blocked integration.
- Use Finnhub through the configured backend for supported numeric data; use a verified yfinance adapter only if available. Obtain filings and company materials through search/read tools. Use licensed connectors only when connected and authorized; this bundle enables none. Record provider coverage and gaps.
- Use original documents for evidence, not search snippets. Distinguish observed facts, management claims, consensus, and agent estimates. Record publication time, retrieval time, reporting period, units, and cutoff. Never label an estimate as consensus without an accessible dated source.
- Compute financial features through versioned deterministic code/SQL or spreadsheet formulas. Do not copy upstream illustrative numbers, screen thresholds, or sample formulas as production rules. Never change active screen rules implicitly.
- Correct methodology pitfalls in upstream comps: EBITDA is not gross profit plus D&A; use an explicitly reconciled definition. Margin ordering is a diagnostic, not an invariant. Undefined or economically meaningless multiples are null/NM with reasons, never silently zero. Distinguish medians, unweighted means, and weighted aggregate ratios. Document EV adjustments, metric definitions, and fiscal-period alignment.
- Keep company/security identity, many-to-many theme membership, evidence, observations, claims, and evaluations separate. Theme metadata supplies context, never assumed company facts. Configure SaaS, AI applications, semiconductors, and robotics through the same tracker interface.
- Require each proposed thesis to state the mechanism, observed versus expected outcome, evidence for what the market expects (or a gap), measurable catalyst, horizon, and invalidation condition. State the strongest supported conclusion with confidence; do not manufacture mispricing or certainty to fill a template.
- Research conclusions may publish only under the saved policy. Default thesis or membership changes to proposals. Upstream increase/trim/exit wording is analytical discussion, not permission to trade or modify holdings.
- Keep slow research independent of numeric snapshot publication. Save evidence checkpoints, record unfinished work, and check input revisions before publishing. Do not assume Dot task completion proves publication or exactly-once execution.

## Working sequence

1. Load the current universe/tracker, thesis revision, prior evidence, numeric snapshot, and data cutoff. Record missing context explicitly.
2. Select workflows through the harness profile. A general ticker request executes the full applicable pipeline. For an explicitly bounded fact question or configured daily/weekly evidence delta, use its narrow scope and reuse a valid dated baseline where appropriate; do not label that delta a fresh complete valuation.
3. Research within the task's scope and budget. Verify primary sources and actively seek counter-evidence. An unchanged thesis may still have incomplete coverage; disclose what was checked.
4. Produce the structured result specified in the integration contract. Keep calculation provenance and citations attached to individual claims.
5. Run the harness's evidence, coverage, dependency, numerical-audit and independent-review gates; inspect warnings and unresolved findings. Validate numerical definitions, freshness and input revisions. Publish through an available authorized backend command and retain receipts, or return an explicitly unsaved/partial draft. Never overwrite a newer thesis.
6. Brief the user on material changes, implications, confidence, and remaining gaps; link detailed evidence when available. Do not add a company-news feed to the minimal app.
