## What the comparison actually checks

The arms collected sources without authoring their own scored answers. One common
extractor read a neutral pool of 11 distinct document bodies. Two independent
reviewer sessions received opposite orders without arm labels. All 32 extracted
observations had literal source spans; 29 were judged answer-bearing. Four shared
SDK observations were bound to both arms, producing 36 arm-bound observations.
Both review orders returned the same primary counts. This was packet blinding on
a shared filesystem, without OS isolation or a human-calibrated absolute judge.

Support means that a passage supports a claim at its stated scope. An anonymous
renewal report remains an anonymous report, management guidance remains guidance,
and a documented mechanism is not a measured production result. Company-wide
subscription revenue was excluded from direct AI-question credit. An AI ACV
threshold was not relabeled as recognized revenue. The raised $1.7 billion AI ACV
target was kept distinct from an actual result and the older $1 billion target.

Both arms touched all three broad topics. That is not evidence that all twelve
underlying information gaps were resolved. Freshness classifications disagreed
on four shared SDK observations, or eight arm-bound instances. All authenticated
first-availability times remained unknown. A opened a newer quarterly release
than B; this demonstrates source selection in this window, not monitoring lag.

## Trace-supported next intervention

Search snippets were preserved in both arms. No native transport failures,
retries, cache hits or alternative readers occurred in the primary pair. Both
arms used some early source feedback, but spent their remaining search budget
before several later opens. B's technical configuration open largely returned
navigation, and A's Microsoft integration URL returned a generic Dynamics page.
The latter supplied only a scoped alternative-product description, not evidence
of ServiceNow integration or a comparable production outcome.

The cheapest next change is a bounded source-reading repair followed by a
missing-question check. Native `find` and a targeted open can inspect a promising
document before another broad search. Give this ordinary capability to **both**
arms. A's differentiated intervention should be explicit gap-driven query/source
selection, not an artificially weaker reader for B.

A separate fixed-URL reader experiment recovered three configuration mechanisms
through native window inspection. Subsequent two-item controls retained both a
content miss and a successful article read through a predeclared known line
anchor. Native `find` did not return the requested matching text in either
control; generic line hints must not be presented as match locations. Its useful
locator behavior remains unverified. One EgoLite attempt returned loading
and cookie content without an answer-bearing configuration passage. This is a
reader-specific result; it does not establish general reader superiority or
belong inside the old pair's counts. EgoLite remains a conditional alternative
for an observed rendered-content need.

## How professional retrieval methods inform the next round

[TREC Novelty](https://trec.nist.gov/data/t13_novelty/novelty04.guidelines.html)
separates relevance from novelty and explicitly uses a selected, incomplete
document collection. Our combined judged pool is likewise a bounded reference;
unknown or unjudged material cannot be treated as irrelevant, and its coverage
must not be called whole-web recall.

[Azure agentic retrieval](https://learn.microsoft.com/en-us/azure/search/agentic-retrieval-overview)
uses query decomposition and merged retrieval, while documenting extra cost and
latency. Its [retrieve API](https://learn.microsoft.com/en-us/azure/search/agentic-retrieval-how-to-retrieve)
exposes subquery activity and partial source failures. Applied here, each next
query should name the unresolved requirement and the observed reason for it;
the trace should preserve partial failures rather than turn them into success.
These documents motivate a small feedback record, not adoption of another search
service or a performance guarantee. The preview limitations also matter.

[MMR](https://www.cs.cmu.edu/afs/.cs.cmu.edu/Web/People/jgc/publication/MMR_DiversityBased_Reranking_SIGIR_1998.pdf)
motivates redundancy-aware selection. Keep novel information, independent
corroboration, contradiction and background separate, so semantic similarity does
not delete useful corroboration. Counts of supported economic units are an
operational richness measure, not Shannon information in bits.

Before another collection, freeze twelve requirement-specific answer fields,
source-role strata, support and novelty rules, budgets and negative controls.
Track which source fields are filled, partial or unknown, alongside new units;
never count mere topic mention as completion. Reserve some search/read budget for
feedback after inspecting sources. Log every variation, retain ties and failures,
and use a different company or later collection window for confirmation. The
current NOW workload is now development evidence.
