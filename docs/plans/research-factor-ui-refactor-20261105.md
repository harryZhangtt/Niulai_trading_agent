# Core research and factor UI refactor

## Objective and scope

The user identified Research evidence and Factor mining as the key workflows after
scheduler UI acceptance. Preserve the current product truth and improve the paths
from subject to source/run evidence and from immutable factor run to performance,
factor and admission evidence. This is frontend presentation/navigation work;
no source acquisition, protected evaluation, registry seeding, dispatch, trading,
promotion, hook or delivery effect is introduced.

Scope/planning fanout recovered the business contracts and found concrete state
mismatches: run/source filters could retain an unrelated inspector, browser Back
was not synchronized, successful stale fallback could look complete/fresh, and an
unknown factor run could silently resolve to the first run. Root owns shared
research shell, source inspector and request-location state; one owner implements
the evidence ledger/overview, another the factor workspace and a third the tests.
Native Harry UI is restored in the primary thread with frontend-design,
Impeccable operate/craft, React, async-state and local browser guidance. Reuse the
existing navy/blue tokens, native controls and retained plotting components.

## Research evidence path

Subject -> evidence readiness/gaps -> run/source selection -> original link,
publication/availability/fetch/recorded times -> linked execution -> exact
run-bound evidence. Lead with metadata and accessible relationships. Keep local
JSON, classification policies, hashes and eligibility diagnostics secondary but
reachable. Distinguish captured body not projected, local body missing and actual
source verification. Date-only precision and Unknown values remain intact.

Filter counts and run health must name their loaded-page/subject denominators.
URL and browser history select the exact subject/run/source; a missing identity
must stay missing. Changing a run/filter must not present another run's evidence.
Successful stale fallback and request failure are different dated states.

## Factor path and truth boundary

The current live registry is empty. Show one explanatory evidence workflow with
No run evidence at every step, not invented operational-ready or failed stages.
No demo/fixture registry is seeded. Once immutable manifests exist, show run
outcome/provenance before hashes/resources, then Performance, Factors and
Evidence views. Preserve every supplied gate, stage, attempt/failure, artifact,
limitation and structured observation.

Factor selection scopes standalone, containing-combination and leave-one-out
observations. A leave-one-out observation measures the combination without a
factor; it is not a paired marginal estimate. Do not subtract confidence intervals
or fabricate contribution uncertainty. Retain metric/unit/period/baseline cohort
matching, common plot scales, sample/uncertainty/provenance and exact table
alternatives. Synthetic, reported, legacy, missing, unavailable and withheld
states stay distinct. Execution success cannot become admission or positive EV.

## Acceptance and evidence

- Exact subject/source/run links and browser Back restore the correct identity.
- Unknown/excluded identities never silently select another evidence record/run.
- Stale/partial/error state is independently visible and date-labelled.
- Evidence dates, body state, labels and relationships remain truthful/complete.
- Empty factor live API remains empty, with no seeded rows/charts/rankings.
- Factor selection and evidence views preserve all chart/table/gate semantics.
- Keyboard/mobile detail/back focus, 320px and200% text remain usable.
- Existing malformed/race/privacy/read-only and metric/provenance tests remain.
- Typecheck/build, research/factor browser and server suites pass; inspect real
  desktop/mobile captures and a guarded live read-only journey.

These are deterministic UI development criteria, not a blinded usability study,
measured research alpha or business runtime acceptance. Preserve failed runs and
unknown delivery fences. Final results and limitations are recorded in the
component runbooks after verification.
