# Atomic capability validation round

Runtime-engine, control-platform and UI expansion are deferred. This round uses
existing acquire/read/compare actions and the existing runner only as a test host.

| Real open question | What the result must establish | High-consequence mistake caught |
| --- | --- | --- |
| What GAAP and adjusted EPS did NVIDIA report for Q1 FY2025, and what bases matter? | Correct values, accounting labels, historical/share basis and actual source passages | Treating different accounting or split bases as conflicting identical facts |
| Can this old release answer today's latest-quarter request? | Distinguish historical revenue, management guidance and unresolved current data | Rejuvenating old facts with retrieval time; forecast promoted to reported result |
| What drives FlashAttention-3 performance, under which controls, and what investment conclusions follow? | Exact revision, mechanism, H100 setup/timing and limits of kernel-to-business inference | Unsupported end-to-end/demand extrapolation; benchmark repetitions called independent evidence |
| Which revenue observations can be reconciled? | Execute raw-unit, different-period and normalized comparisons; retain precision and shared lineage | Unit/column mismatch, invented dates, post-hoc tolerance or fake source independence |

Questions and output types are in `tuning/evals/atomic_actions/cases.json`.
Separate source-grounded expectations are in `oracle.json`; worker packets contain
no expected answers or pass labels. The oracle and grader closure are sealed
before scheduling. Four questions share two original public documents and are
correlated development cases, not a blind generalization/alpha benchmark.

Use neutral answers, typed claims and citations. Required reads/calculations are
verified from host records; the host then reviews each actual answer and source
under the frozen critical criteria. The manual review is bound to answer/source
references and oracle digest. Mechanical keyword checks alone cannot accept it.
Blocked cases still receive full-roster failed grading; unknown call/token/cost
metrics remain unknown. Budget maxima may use explicit conservative enforced
upper bounds for blocked cases, never fabricated observed zeros.

Atomic negative probes cover wrong output schema, inconsistent error/retry
receipts, missing failure receipts, release drift, descriptor misrepresentation,
metadata/corrupt source reads, numeric/definition/unit/period failures, service
error bodies under HTTP200, and worker timeout/overflow/crash/descendant cleanup.
The process-group guard is cleanup, not an adversarial sandbox. Invalid proposals
are rejected before effect intent so bounded argument correction remains possible.

The new worker tests reproduced real boundary failures and a Darwin tiny-timeout
race; prior logs and pinned1.1.0bundles remain historical. Action1.1.1repairs are
separate immutable versions. No provider, global setting, active MCP entry or
production allocation was added.
